Ce rapport devait dire, sans détour, quels serveurs SQL d'AstraVale vont mal, pourquoi, et par quoi commencer. Chaque page pose une seule question et y répond avec un grand visuel, un panneau qui en tire les constats et un titre qui résume la page.

Des boutons font changer de vue dans chaque page : l'ensemble des systèmes ou seulement ceux qui se dégradent, les évolutions ou les alarmes, la mémoire ou l'engorgement. Les visuels sont construits en HTML, CSS et JavaScript à partir du modèle : on survole un point, une barre ou une heure pour voir le détail, et les textes suivent les données.

### Les pages
- **Synthèse** : comment vont les systèmes. Une carte des 7 sites, un tableau des 10 systèmes SQL avec leur statut, leur valeur d'équipement et leur évolution depuis août.
- **Problèmes** : par où commencer. Les 8 métriques de chaque système comparées à août, les heures d'alarme et la priorité selon l'équipement en jeu.
- **Causes** : pourquoi certains serveurs saturent. Les profils de mémoire heure par heure, et l'enchaînement qui va du CPU aux sessions bloquées.
- **Liens** : partager un site ou un flux de données change-t-il quelque chose. La charge disque jour par jour des systèmes qui dépendent les uns des autres.
- **Actions** : que faire en premier. Ce qui arrive si on ne fait rien, et neuf actions qu'un curseur reclasse entre ce qui casse d'abord et ce qui protège le plus de valeur.

Une icône d'information sur chaque page explique les termes et les seuils utilisés.

**Technologies :** Power BI · Power Query (M) · DAX · HTML / CSS · JavaScript
